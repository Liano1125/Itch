# itchPocket UI 改版方案

> 目标：借鉴 GameStoryLog 的游戏整理体验与暗色视觉语言，结合 itch.io 的独立游戏定位，打造更像原生 iOS 产品的游戏发现与收藏工具。
>
> 原则：只借鉴交互模式与视觉表达，不复制品牌素材、页面结构或成人向内容；**不提供游戏下载、下载队列或本地游戏文件管理**。

## 设计方向

- **视觉基调**：深色优先但尊重 iOS 外观设置；以游戏封面作为主要视觉内容，使用高对比标题、低干扰辅助信息、适量半透明材质和柔和圆角。
- **品牌强调色**：以 itch.io 的珊瑚红作为少量强调色，用于主要操作、选中状态和重点标签，避免大面积铺色。
- **原生体验**：优先 SwiftUI 原生导航、系统搜索、触觉反馈和自适应布局；网页仅作为 itch.io 搜索/浏览及原始游戏页面的内容来源。
- **信息真实性**：没有真实数据的统计、评分、游玩时长和更新状态一律不展示，不用演示数字伪装成用户数据。

## 四个核心页面

### 1. Discover（发现）

- 顶部品牌标题与简短说明，建立清晰的页面入口。
- 搜索游戏或开发者，支持键盘提交和清空。
- 用精选、免费、全部游戏等入口作为快捷浏览分类。
- 后续可增加平台、价格、标签筛选；筛选结果仍以 itch.io 可验证的数据为准。
- 不在本地硬编码“热门游戏”或虚构推荐数据。

### 2. Game Detail（游戏详情）

- 封面作为首屏主视觉，标题、开发者和平台信息紧随其后。
- 游戏介绍使用易读的段落宽度与明确层级。
- 可逐步增加截图、标签、开发者主页、相关作品和更新记录（仅在能稳定取得来源数据时）。
- 保留“在 itch.io 查看完整页面”作为来源与完整信息入口。
- 主要个人操作应是“加入游戏库/修改状态”，不是下载。

### 3. Library（游戏库）

- 游戏封面网格与列表视图可切换。
- 支持搜索、状态筛选、排序和下拉刷新。
- 计划状态：想玩、在玩、已更新至最新内容、已完成、暂时搁置、已放弃。
- 支持自定义列表、个人备注、收藏和状态变更记录。
- 状态、备注和自定义列表应保存在本地持久化层；未来如需跨设备同步，再单独设计同步方案。

**当前实现边界：** 现有 Library 从一个固定的 itch.io 公开合集读取游戏，并非当前登录用户的完整个人游戏库。改版不能把这个公开合集误标为账号私有库。下一阶段应先明确数据来源和本地管理模型，再切换真实个人库体验。

### 4. Profile（我的）

- 账号卡片：头像、显示名称、用户名、连接状态。
- 账号操作：登录、打开 itch.io 个人主页、退出登录。
- 设置入口：外观、关于、隐私与数据说明。
- 统计面板只有在具备真实的本地记录后才启用；不展示虚构游玩时长或完成率。

## 实施优先级

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| P0 | 四页统一视觉语言、导航与卡片样式 | iPhone 上布局一致、可读、无功能回退 |
| P1 | 本地游戏状态、备注、收藏 | 杀进程重开后数据仍在；不影响 itch.io 原始页面 |
| P2 | 自定义列表、筛选、排序、网格/列表切换 | 操作结果可预测，空状态/错误状态齐全 |
| P3 | 统计、更新提醒、相关游戏 | 仅展示有来源的数据；提醒可关闭 |

## 视觉细节建议

- 封面卡片优先使用接近 16:10 的比例，统一圆角与裁切方式。
- 卡片标题最多两行，开发者和平台信息降一级显示。
- 页面背景与卡片背景采用系统自适应颜色，避免强制固定纯黑。
- 半透明材质只用于搜索框、浮层或少量重点卡片，避免全屏玻璃效果影响文字对比度。
- 加载、空内容、网络错误和无搜索结果均设计独立状态。
